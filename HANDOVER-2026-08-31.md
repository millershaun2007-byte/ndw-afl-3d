## 5. Deploy rules for this repo — they differ from ndw-footy's

- Builds here are **uncompressed** (`.wasm`/`.data`, no `.br`).
- **`gsutil -m` hangs on this machine.** Use `gcloud storage cp`. (`gsutil` with
  a `-h` header override is still needed where a header must be set.)
- **Upload `index.html` with `--cache-control="no-cache, max-age=0"`.**
- **Verify with the BARE url, not a query string.** GCS serves a stored copy on
  the bare URL for up to an hour; adding `?x=1` bypasses that cache and shows
  you the new file while a real browser still gets the old one. This caused
  Shaun to test and report on a stale build twice in one night.
- **Never overwrite the same object paths with a different build.** The
  cache-bust is a query string and GCS ignores queries for object lookup, so a
  browser can hold `WebGL.data` from build A and fetch `WebGL.wasm` from build
  B. Mismatched pair = a wasm error that looks like a broken build. Deploy each
  build to its own directory.

## 6. Traps found on 31 Aug — all real, all cost time

**Unity 6000.5**
- `Object.GetInstanceID()` is a compile **error** (CS0619), not a warning.
  `GetEntityId()` returns an `EntityId` whose implicit `int` cast is *also* an
  obsolete-as-error. Avoid both; there is usually no need for an id.

**Characters / rigging**
- `EnsureAnimatorController(species, folder)` takes the species as an argument,
  but `BuildStaticCharacter` **derives it from the model folder name**. If they
  disagree the controller is written to one path and looked up at another,
  `LoadAssetAtPath` returns null silently, and the character animates not at
  all. This already happened once here for the rovers.
- The generated animator's `Idle` state had **no clip**, so a stationary player
  stood in his raw bind pose. The `Running` clips in the project were
  referenced by nothing.
- The game calls `SetTrigger("Kick")` and `SetTrigger("Jump")` against a
  controller that declared neither parameter. **Unity drops a SetTrigger for a
  missing parameter silently** — no kick or jump has ever animated.
- Character library GLBs are 5.8MB each and **4.3MB of that is one embedded
  texture, which every clip file carries its own full copy of** despite being
  read only for its AnimationClip.
- `ShrinkAssets.Run` cannot fix that: textures embedded in a `.glb` have no
  `TextureImporter`, so it reports `textures=0`. The files have to be rewritten
  directly (a Pillow script that keeps each image's bufferView *index* and only
  changes offsets, so nothing needs reindexing).
- **Use `ndw-footy`'s models, not `ndw-character-library`'s.** They are
  different meshes (library Croc 24141 verts / 37207 tris; ndw-footy's
  23134 / 36100) and ndw-footy's are the ones Shaun rates. Its clips are
  extracted `.anim` assets in `ndw-footy/Assets/_Clips`, not sub-assets in GLBs.
- Mia is not in `ndw-footy`. She keeps her own model and takes Croc's clips —
  her skeleton is 24 joints with every path `Armature/Hips/...` identical to
  that batch, verified, so they bind without re-rigging. **Shaun wants Mia
  kept.**
